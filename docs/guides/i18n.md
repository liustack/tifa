# A site in several languages

Tifa has no language settings. The language is a part of the URL, Go checks it, and the pages take it from there. The rules are in [A site in several languages](../app.md#a-site-in-several-languages) and [Content](../content.md), and the shop's storefront in [examples/shop](../../examples/shop/app/store) is a large working copy. This guide builds a small site from the first folder to the tests and ties those pieces together: where the list of languages lives, who picks the language, how the interface and the posts get translated, and how search engines learn which page is which.

The site, `lingo`, has a home page, a list of posts and a post page, in English (`en`, the default) and Chinese (`zh-CN`). One post exists in both languages and one only in English. The code is a real app made with `tifa new`, built and checked with `tifa check`.

## Decisions

- **One URL per language, the default language too.** `/en/posts` and `/zh-CN/posts`. A page is the same for everyone who opens its URL, so it can be kept in the [whole-page cache](../app.md#the-whole-page-cache), linked and found by a search engine. A cookie or `Accept-Language` alone would give one URL two pages.
- **The language comes from the URL, and only from there.** A visitor's cookie and browser language are used once, at `/`, to pick a URL. No page reads them.
- **One list of languages, in Go.** Pages get the list as data. Codes are written the way search engines read them (`en`, `zh-CN`) and used everywhere: in the URL, in the folder names under `content/` and as the keys of the interface strings.
- **Show only what exists.** A post with no Chinese version is not in the Chinese list, and its English page does not claim a Chinese twin. Falling back to English text under a Chinese URL mixes two languages on one page.

## One list of languages

`languages.go` at the root is the only place that lists the languages and their names:

```go
// languages.go
package lingo

// Language is one language of the site.
type Language struct {
	Code string `json:"code"`
	// Name is the language written in itself, for the language switch.
	Name string `json:"name"`
}

// Languages are the languages of the site, the default one first.
var Languages = []Language{
	{Code: "en", Name: "English"},
	{Code: "zh-CN", Name: "简体中文"},
}

// FindLanguage returns the language of a code from the URL, or tifa.ErrNotFound.
func FindLanguage(code string) (Language, error) {
	for _, l := range Languages {
		if l.Code == code {
			return l, nil
		}
	}
	return Language{}, tifa.ErrNotFound
}
```

The content collection must name its languages with a literal in `content.go` ([Declaring a collection](../content.md#declaring-a-collection) says why), so the list is written twice. A test keeps both equal:

```go
func TestLanguagesMatchTheCollection(t *testing.T) {
	var codes []string
	for _, l := range Languages {
		codes = append(codes, l.Code)
	}
	if !slices.Equal(codes, Posts.Languages()) {
		t.Fatalf("Languages %v, Posts.Languages() %v", codes, Posts.Languages())
	}
}
```

## The Layout checks the language

The Layout of `app/lang+` is the one gate. A language the site does not have is a 404, shown by the Layout above ([the pattern](../app.md#a-site-in-several-languages)). The pages below call it with `tifa.Use`, so a page never trusts `c.Param("lang")` itself:

```go
// app/lang+/route.go
package lang

// Shell is what every page shows around itself.
type Shell struct {
	Lang      string           `json:"lang"`
	Languages []lingo.Language `json:"languages"`
}

func Layout(c *tifa.Ctx) (Shell, error) {
	l, err := lingo.FindLanguage(c.Param("lang"))
	if err != nil {
		return Shell{}, err
	}
	return Shell{Lang: l.Code, Languages: lingo.Languages}, nil
}
```

```go
// app/lang+/posts/route.go
func Load(c *tifa.Ctx) (List, error) {
	s, err := tifa.Use(c, lang.Layout)
	if err != nil {
		return List{}, err
	}
	return List{Lang: s.Lang, Posts: Published(s.Lang), SEO: lingo.PageSEO(s.Lang, "/posts")}, nil
}
```

The root Layout has an `Error` that shows for `/fr` and for any URL no page has. The visitor's language is not known there, so it says "Page not found · 页面不存在" and links both languages.

## Choosing a language at `/`

`/` has no page, only a method handler. It sends the visitor to the language they picked before, and otherwise to the closest match for their browser ([Matcher](https://pkg.go.dev/golang.org/x/text/language#Matcher) of `golang.org/x/text/language` knows `en-GB` is closer to `en` than to `zh-CN`):

```go
// languages.go
var matcher = func() language.Matcher {
	var tags []language.Tag
	for _, l := range Languages {
		tags = append(tags, language.MustParse(l.Code))
	}
	return language.NewMatcher(tags)
}()

// Preferred returns the language closest to an Accept-Language header, the default one when
// none is close.
func Preferred(acceptLanguage string) Language {
	tags, _, _ := language.ParseAcceptLanguage(acceptLanguage)
	_, i, confidence := matcher.Match(tags...)
	if confidence == language.No {
		return Languages[0]
	}
	return Languages[i]
}
```

```go
// app/route.go
func GET(c *tifa.Ctx) error {
	c.Writer().Header().Add("Vary", "Cookie, Accept-Language")
	if picked, err := c.Cookie(lingo.LangCookie); err == nil {
		if l, err := lingo.FindLanguage(picked.Value); err == nil {
			return tifa.Redirect("/"+l.Code, http.StatusFound)
		}
	}
	return tifa.Redirect("/"+lingo.Preferred(c.Header("Accept-Language")).Code, http.StatusFound)
}
```

It is a 302, since the answer depends on the visitor, and it says what it depends on with `Vary`. A cookie holding anything but a language of the site is ignored.

### Remembering the choice

Without a cookie, a visitor who switches to Chinese lands on `/` next time and goes back to what their browser says. If that matters to you, keep the choice. If your readers mostly use the language their browser asks for, skip this section: the URL itself is already the memory.

A link in the language switch goes through a small route of Go that sets the cookie and goes on to the page:

```go
// app/lang+/remember/route.go
package remember

func GET(c *tifa.Ctx) error {
	l, err := lingo.FindLanguage(c.Param("lang"))
	if err != nil {
		return err
	}
	c.SetCookie(&http.Cookie{
		Name: lingo.LangCookie, Value: l.Code, Path: "/", MaxAge: int(365 * 24 * time.Hour / time.Second),
		HttpOnly: true, SameSite: http.SameSiteLaxMode,
	})
	to := c.Query("to")
	// Only go on to a page of the language itself. Anything else, such as an address on another
	// site, is dropped, so this URL cannot be used to send visitors elsewhere.
	if to != "/"+l.Code && !strings.HasPrefix(to, "/"+l.Code+"/") || strings.ContainsAny(to, "\\\r\n") {
		to = "/" + l.Code
	}
	c.Writer().Header().Set("Cache-Control", "no-store")
	return tifa.Redirect(to, http.StatusFound)
}
```

- **It lives under `lang+`, not in a folder of its own.** `/pick/{lang}` fails the build: `the path "/pick/{lang}" conflicts with "/{lang}/posts" of app/lang+/posts: both match some URLs and neither is more specific`. A literal folder first and a parameter second cannot sit next to a parameter first and a literal second ([URLs come from folders](../app.md#urls-come-from-folders)).
- **`to` comes from the visitor,** so only a path in the chosen language is followed. A test sends `https://evil.example`, `//evil.example`, a path of the other language and a backslash.
- **The switch link is a plain `<a>`,** not a router `Link`, because the target is a route of Go and not a page.
- **No page reads the cookie.** A page that read it could not be cached, and one URL would show two languages.

## Translating the interface

Interface strings are one JSON file per language, bundled with the app, and one i18next instance per language:

```json
// app/lang+/locales/en.json
{
  "site": { "name": "Lingo" },
  "nav": { "home": "Home", "posts": "Posts", "language": "Language" },
  "home": { "title": "Home", "lead": "Notes from a small studio, in two languages." },
  "posts": {
    "title": "Posts",
    "count_one": "{{count}} post",
    "count_other": "{{count}} posts",
    "published": "Published {{date, datetime(dateStyle: medium; timeZone: UTC)}}",
    "back": "All posts"
  }
}
```

```ts
// app/lang+/i18n.ts
import i18next, { type i18n } from 'i18next'
import en from './locales/en.json'
import zhCN from './locales/zh-CN.json'

// Every message of every language is bundled with the app, so init runs at once and the server
// render has all of them.
const resources = {
  en: { translation: en },
  'zh-CN': { translation: zhCN },
}

const instances = new Map<string, i18n>()

// i18nFor returns the i18next instance of a language, made once per language. The language comes
// from the data of the language Layout, which Go has checked.
export function i18nFor(lang: string): i18n {
  let instance = instances.get(lang)
  if (!instance) {
    instance = i18next.createInstance()
    instance.init({
      lng: lang,
      fallbackLng: false,
      resources,
      initAsync: false,
      interpolation: { escapeValue: false },
    })
    instances.set(lang, instance)
  }
  return instance
}
```

The Layout hands the instance to its pages:

```tsx
// app/lang+/layout.tsx
export default function Language() {
  const { lang } = layout.useLoaderData()
  return (
    <I18nextProvider i18n={i18nFor(lang)}>
      <Header />
      <Outlet />
    </I18nextProvider>
  )
}
```

A page then calls `const { t } = useTranslation()` and writes `t('posts.back')`. The reasons are in [A site in several languages](../app.md#a-site-in-several-languages): everything loads at once (`initAsync: false`), so the server HTML has the text and the browser hydrates with the same text, and the language comes from the Layout's data.

- **Instances live per language, not per request,** and every language has its own, so no request can change what another sees.
- **`fallbackLng: false`.** A key missing in Chinese shows as the key, which you see in review. A silent English fallback hides a gap. Add a test that both files have the same keys if the site grows.
- **Plurals follow the language.** `count_one` and `count_other` for English, only `count_other` for Chinese, which has no singular form. The server has `Intl.PluralRules`.
- **Dates carry their time zone in the message** (`datetime(dateStyle: medium; timeZone: UTC)`), so the server and every browser print the same text ([Formatting so hydration matches](../app.md#formatting-so-hydration-matches)).
- **Page titles are written outside components,** so they use the instance directly: `i18nFor(loaderData.lang).t('posts.title')`.
- **The i18next cache** of the server render is on by default and fine here. See [`build.i18next_cache`](../config.md#settings) for when to turn it off.

## Posts in two languages

`content.go` declares the languages, and the files sit in one folder per language ([Content](../content.md)):

```go
// content.go
var Posts = content.Define[Post](content.Source{Dir: "posts", Languages: []string{"en", "zh-CN"}})

type Post struct {
	content.Entry
	Title   string `json:"title"`
	Summary string `json:"summary"`
}
```

```markdown
<!-- content/posts/zh-CN/hello/index.md -->
---
title: 来自工作室的问候
summary: 我们为什么用两种语言写作。
date: 2026-10-01
slug: ni-hao
---
```

`content/posts/en/hello/index.md` has the same path, so Tifa treats the two as translations of each other ([ID, slug, path and languages](../content.md#id-slug-path-and-languages)). The Chinese URL uses its own slug, `/zh-CN/posts/ni-hao`, and the English one `/en/posts/hello`. `Entry.Translations` lists both with their slugs. A translation with another path joins with `translationKey` in its front matter.

The domain asks the collection for one language at a time:

```go
// app/lang+/posts/post.go
func Published(lang string) []lingo.Post {
	list := lingo.Posts.In(lang) // drafts and posts still to come are left out
	slices.SortStableFunc(list, func(a, b lingo.Post) int { return b.Date.Compare(a.Date) })
	return list
}

func BySlug(lang, slug string) (lingo.Post, error) {
	for _, p := range lingo.Posts.In(lang) {
		if p.Slug == slug {
			return p, nil
		}
	}
	return lingo.Post{}, tifa.ErrNotFound
}
```

`/en/posts/ni-hao` is a 404: a slug belongs to its language. `tifa build` prints one line for what lacks a translation, so you see the gap at every build:

```text
tifa: content: 1 entry of posts has no zh-CN version: only-english (warning)
```

## Links between the languages

Search engines read two kinds of link in the head of a page ([Google's rules for localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions)):

- `rel="alternate" hreflang` for each version of the page, the page itself included, with full addresses (`https://...`), and `x-default` for visitors none of the languages suits. Every version must point back to the others, or the links are ignored.
- `rel="canonical"`, the page's own address, without query strings.

The addresses need the site's public address, which differs per deployment, so it is a setting:

```go
// config.go
var SiteURL = tifa.String("site.url", "http://127.0.0.1:9527", "Public address of the site, without a trailing slash")
```

Set `SITE_URL=https://example.com` on the server. The links are built in Go, next to the data they come from, and travel to the page as part of its `Load` result:

```go
// languages.go
// An Alternate is the same page in another language, with its full address.
type Alternate struct {
	// Lang is a language code, or x-default for visitors none of the languages suits.
	Lang string `json:"lang"`
	Href string `json:"href"`
}

// SEO is what the head of a page needs to tell search engines which page this is and where its
// translations are.
type SEO struct {
	Canonical  string      `json:"canonical"`
	Alternates []Alternate `json:"alternates"`
}

func url(lang, path string) string {
	return strings.TrimSuffix(SiteURL, "/") + "/" + lang + path
}

// PageSEO is the SEO of a page that exists in every language at the same path below the
// language, such as "/posts". Use "" for the home page of a language.
func PageSEO(lang, path string) SEO {
	var alts []Alternate
	for _, l := range Languages {
		alts = append(alts, Alternate{Lang: l.Code, Href: url(l.Code, path)})
	}
	return SEO{Canonical: url(lang, path), Alternates: withDefault(alts)}
}

// PostSEO is the SEO of a post: it lists only the languages the post has.
func PostSEO(p Post) SEO {
	var alts []Alternate
	for _, t := range p.Translations {
		alts = append(alts, Alternate{Lang: t.Lang, Href: url(t.Lang, "/posts/"+t.Slug)})
	}
	return SEO{Canonical: url(p.Lang, "/posts/"+p.Slug), Alternates: withDefault(alts)}
}

// withDefault adds x-default, pointing at the version in the default language when there is one.
func withDefault(alts []Alternate) []Alternate {
	for _, a := range alts {
		if a.Lang == Languages[0].Code {
			return append(alts, Alternate{Lang: "x-default", Href: a.Href})
		}
	}
	return alts
}
```

A page head turns that data into tags:

```ts
// app/lang+/seo.ts
type SEO = { canonical: string; alternates: Array<{ lang: string; href: string }> }

// seoHead gives a page its title and the links search engines read: the page's own address, and
// the same page in each language it has.
export function seoHead(title: string, seo: SEO) {
  return {
    meta: [{ title }],
    links: [
      { rel: 'canonical', href: seo.canonical },
      ...seo.alternates.map((a) => ({ rel: 'alternate', hrefLang: a.lang, href: a.href })),
    ],
  }
}
```

```tsx
// app/lang+/posts/post+/page.tsx
export const head = ({ loaderData }: { loaderData?: PageData }) => (loaderData ? seoHead(loaderData.post.title, loaderData.seo) : {})
```

The Layout sets only `<html lang>`:

```tsx
// app/lang+/layout.tsx
export const head = ({ loaderData }: { loaderData?: LayoutData }) => ({
  htmlAttributes: { lang: loaderData?.lang },
})
```

Why the links come from each page and not from the Layout, as the shop's storefront does: the shop has every page in both languages, so its Layout can write the links for all pages in one place ([the Layout head](../app.md#a-site-in-several-languages)). Here a post may exist in one language only, and only the page knows. Use the Layout way when every page exists in every language, and the page way when translations vary. Both leave the links out when the page fails: a page with no data has no `loaderData`, so its head is empty, and a URL that answers 404 is not pointed to.

What the server sends for the English page of the translated post and for the one with no Chinese version (`SITE_URL=https://example.com`):

```html
<!-- /en/posts/hello -->
<html lang="en"> ... <title>Hello from the studio</title>
<link rel="canonical" href="https://example.com/en/posts/hello">
<link rel="alternate" hrefLang="en" href="https://example.com/en/posts/hello">
<link rel="alternate" hrefLang="zh-CN" href="https://example.com/zh-CN/posts/ni-hao">
<link rel="alternate" hrefLang="x-default" href="https://example.com/en/posts/hello">

<!-- /en/posts/only-english -->
<link rel="canonical" href="https://example.com/en/posts/only-english">
<link rel="alternate" hrefLang="en" href="https://example.com/en/posts/only-english">
<link rel="alternate" hrefLang="x-default" href="https://example.com/en/posts/only-english">
```

The Chinese page of the first post lists the same three alternates, so the links point back and forth.

## The language switch

The switch shows the other languages by name, each written in itself, and goes to the same page in that language. For a post, the same page is the translation, whose slug differs. The page already knows it: the switch reads the links the page's `Load` gave for search engines, and falls back to the home page of the language when the page has no version there.

```tsx
// app/lang+/layout.tsx
function useWhere() {
  const matches = useMatches()
  const seo = (matches[matches.length - 1]?.loaderData as { seo?: { alternates: Array<{ lang: string; href: string }> } } | undefined)?.seo
  return (code: string) => {
    const href = seo?.alternates.find((a) => a.lang === code)?.href
    return href ? new URL(href).pathname : `/${code}`
  }
}

// in Header, for each language that is not the current one:
<a href={`/${l.code}/remember?to=${encodeURIComponent(where(l.code))}`} hrefLang={l.code} lang={l.code} rel="nofollow">
  {l.name}
</a>
```

`lang` on the link marks the name as being in its own language for screen readers, and `rel="nofollow"` keeps crawlers off the cookie route (they find the languages through the alternate links in the head). For a post with no Chinese version the Chinese link goes to `/zh-CN`.

## Test it

```go
func TestPreferred(t *testing.T) {
	for header, want := range map[string]string{
		"":                        "en",
		"zh-TW,zh;q=0.9,en;q=0.5": "zh-CN",
		"en-GB":                   "en",
		"fr-FR":                   "en", // none is close: the default
		"zh-CN":                   "zh-CN",
	} {
		if got := Preferred(header).Code; got != want {
			t.Errorf("Preferred(%q) = %s, want %s", header, got, want)
		}
	}
}

// A post lists only the languages it has, under the slug it has in each.
func TestPostSEOFollowsTheTranslations(t *testing.T) {
	old := SiteURL
	SiteURL = "https://example.com"
	t.Cleanup(func() { SiteURL = old })
	hello := func(lang, slug string) Post {
		return Post{Entry: content.Entry{ID: "hello", Lang: lang, Slug: slug, Path: "hello"}}
	}
	tifatest.SetContent(t, Posts, hello("en", "hello"), hello("zh-CN", "ni-hao"), Post{Entry: content.Entry{ID: "alone", Lang: "en", Slug: "alone", Path: "alone"}})
	en, err := Posts.Get("en", "hello")
	if err != nil {
		t.Fatal(err)
	}
	got := PostSEO(en)
	want := []Alternate{
		{"en", "https://example.com/en/posts/hello"},
		{"zh-CN", "https://example.com/zh-CN/posts/ni-hao"},
		{"x-default", "https://example.com/en/posts/hello"},
	}
	if !slices.Equal(got.Alternates, want) || got.Canonical != "https://example.com/en/posts/hello" {
		t.Fatalf("PostSEO: %+v, want %+v", got, want)
	}
}
```

The rest follows the same shape: `GET` of `/` with each header and cookie, the `remember` route with addresses that must not be followed, `Load` of a language the site does not have returning `tifa.ErrNotFound`, and `BySlug` finding a post by the slug of its own language. `tifatest.SetContent` gives tests their entries without a build ([reading content in tests](../content.md)).

## Adding a third language

1. Add it to `Languages` in `languages.go` and to `Languages` in `content.go`. The test fails until both match.
2. Add `app/lang+/locales/<code>.json` and its entry in `resources` of `i18n.ts`.
3. Add `content/posts/<code>/` and translate what you can. The build lists what is missing.

Nothing else changes: the routes, the Layout, the links and the switch all read the list.
