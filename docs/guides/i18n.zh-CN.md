# 多语言网站

你有一个网站，想让每个访客用自己的语言读它。做完之后，每种语言有自己的 URL，界面文字翻译好了，每个页面在 `<html lang>` 里写明自己的语言，搜索引擎拿到把页面各个版本连起来的 `hreflang` 链接。

一个目录里有 `_locales` 目录，它就是多语言的。声明就这些：Go 里没有语言列表，没有路由常量，目录名里也没有语言参数。下面的代码来自 [test/apps/i18n](../../test/apps/i18n)，[examples/shop](../../examples/shop/app/store) 的店面是一份大的可运行样例，默认英文。每个设置的细节见 [config.zh-CN.md](../config.zh-CN.md)，Tifa 生成的文件见 [build.zh-CN.md](../build.zh-CN.md)。

## 加上语言

在要多语言的目录里放一个 `_locales` 目录，每种语言一个 JSON 文件。一个中英文店面，默认中文：

```text
app/
  store/
    _locales/
      zh-CN.json
      en-US.json
    page.tsx             /store 和 /en-US/store
    cart/page.tsx        /store/cart 和 /en-US/store/cart
    mine/route.go        /store/mine 和 /en-US/store/mine（一个 API 路由）
  projects/page.tsx      只有 /projects
```

有 `_locales` 目录的目录叫一个区，它的语言就是 `<language>.json` 文件的名字。区里和区下面的每个页面和 API 路由都有这些语言。不在任何区里的路由没有语言，只有一个 URL。把 `_locales` 放在 `app/` 本身，整个网站就是一个区。下面再有一个区时，它自己的路由用它自己的语言，不用上面那个的。

文件名必须是写法规范的语言标签：`en-US`，不是 `en_US` 或 `en-us`。然后在 `tifa.yaml` 里写默认语言和网站的地址：

```yaml
i18n:
  default: zh-CN
site:
  url: https://shop.example.com
```

只有一种语言时可以不写 `i18n.default`。有多种时必须写，它得是其中一种，而且每个区都要有它的文件。`site.url` 是网站对外的协议和主机，不带路径。`hreflang` 链接要完整的地址，从请求猜在 CDN 后面会猜错。这两项都只能写在项目文件里，和 `build.*` 一样。

## URL

默认语言不带前缀。其他语言把语言放在路径第一段：

| URL | 响应 |
| --- | --- |
| `/store/cart` | 默认语言 `zh-CN` 的页面 |
| `/en-US/store/cart` | `en-US` 的页面 |
| `/zh-CN/store/cart` | 308 跳到 `/store/cart` |
| `/en-US/projects` | 404：`/projects` 不在任何区里，没有 `en-US` |
| `/fr/store/cart` | 404，因为店面没有 `fr` 文件 |

所有重定向都保留查询参数。路由匹配之后，带前缀的 URL 就是这个请求的 URL：整页缓存、渲染缓存、ETag 和重定向用的都是带前缀的 URL，所以同一个路径的两种语言不会共用一份缓存。

在 `tifa.yaml` 里写 `i18n.prefix: always`，默认语言也带前缀。这时 `/store` 用 308 跳到 `/zh-CN/store`。不在任何区里的路由不变。

```yaml
i18n:
  default: zh-CN
  prefix: always
```

构建不接受两件事：`app/` 顶层有目录和网站某种语言同名（`app/en-US/` 会成为那种语言 URL 的第一段），以及在 `htmlAttributes` 里写 `lang`，因为 `<html lang>` 由 Tifa 写。

## 在代码里取语言

Go 里，`c.Language()` 给出正在响应的路由的语言。在 `Load`、`Layout`、方法函数和 API 路由里都能用：

```go
// app/store/route.go
func Load(c *tifa.Ctx) (Data, error) {
	return Data{Language: c.Language(), Q: c.Query("q")}, nil
}
```

React 里，`tifa/client` 的 `useLanguage()` 给出同一个值：

```tsx
import { useLanguage } from 'tifa/client'

const language = useLanguage() // "zh-CN" 或 "en-US"
```

在有多种语言的网站上，区外的路由两者都给默认语言。没有语言的网站给 `""`。Tifa 为区里的方法函数生成的函数会带着当前的前缀去请求，所以方法函数里的 `c.Language()` 和调用它的页面一样。

测试里，`tifatest.NewCtx` 造出的 Ctx 用请求路径的语言：`httptest.NewRequest("GET", "/en-US/store/mine", nil)` 得到 `en-US`，没有前缀的路径得到默认语言。

## 翻译界面

核心不带翻译库。Tifa 在 `tifa/i18n` 里提供 [i18next](https://www.i18next.com/) 和 react-i18next 的适配器。先装这两个包：

```sh
pnpm add i18next react-i18next
```

网站有语言、`package.json` 又列了 `react-i18next` 时，Tifa 把适配器写进 `.tifa/`。`tifa new` 写出的 `tsconfig.json` 已经映射了 `tifa/i18n`。

文案是嵌套的 JSON，每种语言一个文件：

```json
{
  "title": "店面",
  "cart": { "title": "购物车", "items_other": "{{count}} 件商品" }
}
```

区的命名空间是它相对 `app/` 的目录：`app/store/_locales` 是 `store`，`app/admin/store/_locales` 是 `admin/store`，`app/_locales` 是默认命名空间。在根 Layout 里包一次 `I18nProvider`：

```tsx
// app/layout.tsx
import { Outlet } from '@tanstack/react-router'
import { I18nProvider } from 'tifa/i18n'

export default function Shell() {
  return (
    <I18nProvider>
      <Outlet />
    </I18nProvider>
  )
}
```

然后用常见的 hook 翻译：

```tsx
// app/store/cart/page.tsx
import { useTranslation } from 'tifa/i18n'

export default function Cart() {
  const { t } = useTranslation('store')
  return <h1>{t('cart.title')}</h1>
}
```

每种语言都和应用一起打包，所以服务器渲染和浏览器都有全部文案，什么都不用另外取。金额之类的格式化函数，在根 Layout 加载的模块顶层调一次 `setupI18n`，它会对每种语言各跑一次：

```tsx
import { setupI18n } from 'tifa/i18n'

setupI18n((i18n, language) => {
  i18n.services.formatter?.addCached('currency', (lng, options) => {
    const f = new Intl.NumberFormat(lng, { currency: 'USD', ...options, style: 'currency' })
    return (value) => f.format(value)
  })
})
```

`Intl` 调用要自己传语言，服务器和浏览器才会输出同样的文字（见[怎么写才能水合一致](../app.zh-CN.md#怎么写才能水合一致)）。更多见[i18next 适配器](../build.zh-CN.md#i18next-适配器)。

区在某种语言里没有文案时，也要有它的文件：写 `{}`。没有对应文案的 key 会显示 key 本身。Tifa 不会去别的语言里找。

## 链接和语言切换

链接照只有一种语言的网站那样写：

```tsx
<Link to="/store/cart">购物车</Link>
```

在 `en-US` 的页面里，Tifa 把它变成 `/en-US/store/cart`，并在原地跳转。去区外的路由（比如 `/projects`）的链接，或者指明了另一种语言的链接，会加载新页面，因为一个页面只有一种语言。`navigate`、`Load` 里的重定向和内容条目 HTML 里的链接也一样。这些都不用你写。

Go 里的重定向也按这条规则：响应 `en-US` 请求时，`tifa.Redirect("/store/cart", 303)` 跳到 `/en-US/store/cart`。以某种语言开头的路径，比如 `/zh-CN/store/cart`，照写的去。

做语言切换用 `tifa/client` 的 `useAlternates()`，它给出当前页面每种语言的 URL。用普通的 `<a>` 链过去，因为另一种语言是另一个页面：

```tsx
import { useAlternates, useLanguage } from 'tifa/client'

const names: Record<string, string> = { 'zh-CN': '中文', 'en-US': 'English' }

export function LanguageSwitch() {
  const versions = useAlternates()
  const current = useLanguage()
  return (
    <nav>
      {versions.map((v) => (
        <a key={v.language} href={v.url} aria-current={v.language === current ? 'page' : undefined}>
          {names[v.language]}
        </a>
      ))}
    </nav>
  )
}
```

只有一个版本的页面和区外的页面，这个列表是空的，所以切换在那里什么都不显示。

## 搜索引擎拿到什么

页面有不止一个版本时，Tifa 往 head 里加：

- 每个版本一个 `<link rel="alternate" hreflang="...">`，页面自己的也在内
- `hreflang="x-default"`，指向默认语言的版本
- 页面自己的 `<link rel="canonical">`

地址是完整的，由 `site.url` 拼成，不带查询参数。你在自己的 `head` 里写的 canonical 比 Tifa 的优先。404、错误页和只有一个版本的页面没有这些链接。

默认情况下，区里的页面在每种语言里都存在，路径相同，只是前缀不同，带参数的页面也一样。页面在另一种语言里用了别的 slug，或者只有一种语言，这样就不对了。在页面的 `Load` 里用 `c.SetAlternates` 说明。每个路径写成访客看到的样子：已转义，不带前缀和查询参数，页面自己也要列进去：

```go
// app/store/journal/slug+/route.go
func Load(c *tifa.Ctx) (Data, error) {
	slug := c.Param("slug")
	translations, ok := entries[slug] // 比如 {zh-CN, ni-hao}、{en-US, hello}
	if !ok {
		return Data{}, tifa.ErrNotFound
	}
	var versions []tifa.Alternate
	for _, t := range translations {
		versions = append(versions, tifa.Alternate{Language: t.Lang, Path: "/store/journal/" + t.Slug})
	}
	c.SetAlternates(versions)
	return Data{Slug: slug}, nil
}
```

hreflang 链接和 `useAlternates()` 都按这个列表走，所以切换会把 `/store/journal/ni-hao` 连到 `/en-US/store/journal/hello`。列表里没有的语言，这个页面就没有那个版本。空列表表示页面只有一个版本。语言不是这个页面的语言之一、同一种语言列了两次、或路径不是普通的已转义路径时，页面会失败并在日志里写出原因。

## 每种语言的文章

内容集合写 `Languages: tifa.Languages()`，`content/` 下每种语言一个目录：

```go
// content.go
var Journal = content.Define[Entry](content.Source{Dir: "journal", Languages: tifa.Languages()})
```

```text
content/journal/
  zh-CN/hello.md
  en-US/hello.md
```

`tifa.Languages()` 是网站的所有语言，默认语言在最前。在 `tifa build`、`tifa dev`、`go test` 和 `go run` 下它给出同一个列表。用 `c.Language()` 读条目：

```go
e, err := Journal.Get(c.Language(), "hello")
```

缺某种语言的条目，在那种语言里就没有页面：`Get` 返回 `tifa.ErrNotFound`，页面是 404，也不回退到别的语言。用 `date` 定时发布的译文到点自己出现。`entry.Translations` 列出现在能看到的版本，条目页就用它去调 `SetAlternates`。其余见[内容](../content.zh-CN.md)。

Markdown 里的链接写成根相对路径，比如 `[购物车](/store/cart)`。构建时，路由有条目这种语言，就给链接加上条目语言的前缀：`en-US` 的条目里是 `/en-US/store/cart`。已经以某种语言开头的链接保持原样。

## 从 `lang+` 目录迁过来

把语言放在 `lang+` 目录里、又没有 `_locales` 目录的应用，照旧能用。要迁过来：

1. 把页面和 `route.go` 从 `lang+` 目录挪到它的上一层，文案写成那里的 `_locales/<language>.json`。
2. 删掉检查语言的 `Layout`、它的 `head` 里的 `lang` 和手写的 `hreflang` 链接，这些由 Tifa 写。
3. 原来读 `params.lang` 的地方，改用 `c.Language()` 和 `useLanguage()`。
4. 不再需要的话，删掉 `/store` 按 `Accept-Language` 或 cookie 做的重定向：`/store` 现在就是默认语言的页面。

## 开发时

- `tifa dev` 不用重启就能认出新加的 `_locales/fr.json`，`/fr/store` 马上能访问。删掉文件它就 404。
- `fr.draft.json` 不发布。文件改名成 `fr.json` 之前，网站就没有这种语言。翻译做到一半时用它。
- 直接 `go test` 时 `tifa.Languages()` 也能用，它读模块里的 `_locales` 目录和 `tifa.yaml`。

## 什么会让构建失败

`tifa build` 和 `tifa check` 会报出文件和原因并停下，当：

- 某个区没有默认语言的文件
- 有多种语言却没有 `i18n.default`，或者它写的语言没有哪个区有
- 有多种语言却没有 `site.url`
- 文件名不是写法规范的语言标签
- 某个 `_locales` 目录里一个语言文件都没有
- `app/` 顶层有目录和网站某种语言同名
- 有语言的网站在 `htmlAttributes` 里写了 `lang`
- 内容集合的 `Languages:` 既不是 `tifa.Languages()`，也不是字符串字面量的列表

## Tifa 不做什么

- 不替访客选语言。没有按 `Accept-Language`、cookie 或地址做的重定向。URL 就是选择，所以每个 URL 对所有人都是同一个页面，搜索引擎能收录，也能放进[整页缓存](../app.zh-CN.md#整页缓存)。想把第一次来的访客送到他的语言，就在区外的路由上写一个处理函数，不开 `Cache`。
- 不记住选择。想记住的话，在访客选语言时由应用设一个 cookie，再在上面那个处理函数里读它。
- 没有回退语言。缺的文案显示 key，缺的条目是 404，区没有文件的语言也是 404。
