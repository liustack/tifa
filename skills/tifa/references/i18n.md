# A site in several languages

Contents: declaring the languages, the URLs, the language in code, translations, links and the language switch, search engine links, the page with no language.

Full docs (in the folder `go tool tifa docs` prints): `docs/app.md#a-site-in-several-languages`. The step-by-step guide is `docs/guides/i18n.md`.

A folder with a `_locales` folder is in several languages. There is no list of languages in Go, no language folder like `lang+` and no Layout that checks the language.

## Declare the languages

- Put a `_locales` folder in the folder that is in several languages, with one JSON file per language named by its tag in the usual spelling: `app/store/_locales/zh-CN.json` and `en-US.json`. The folder and everything below it is one area. A route outside every area has one URL and no language.
- In `tifa.yaml`, `i18n.default` names the default language (every area needs a file for it) and `site.url` is the scheme and host of the site, with no path. Both are project file settings. `i18n.prefix: always` puts the default language in the URL too.
- An area with nothing to say in a language still needs its file: write `{}`. `fr.draft.json` is a translation in progress and is not published.

## The URLs

The default language has no prefix, any other language is the first segment: `/store/cart` is `zh-CN` and `/en-US/store/cart` is `en-US`. `/zh-CN/store/cart` answers 308 to `/store/cart`. A language the area has no file for is a 404. The prefix is part of the URL for the render memo, ETags and CDNs, so each language has its own entries.

## The language in code

- Go: `c.Language()` in a `Load`, a `Layout`, a method handler or an API route. In `tifatest.NewCtx` it is the language of the request path.
- React: `useLanguage()` from `tifa/client`.
- `tifa.Languages()` is the list for the site, the default first. It works under `go test` too.
- Never read the language from `params`. Do not write `<html lang>` or put a `lang` in `htmlAttributes`: Tifa writes it, and a `lang` in `htmlAttributes` fails the build on a site with languages.

## Translations

- Install `i18next` and `react-i18next` (`pnpm add`). Wrap the app once in the root Layout with `I18nProvider` from `tifa/i18n`, and use `useTranslation('store')` from `tifa/i18n`. The namespace is the folder of `_locales` relative to `app/` (`app/store/_locales` is `store`, `app/_locales` is the default namespace). Outside a component use `i18n.t('store:key')` with `i18n` from `tifa/i18n`.
- Every language is bundled with the app and nothing is fetched, so the server render and the browser have the same strings. A key with no string shows the key. There is no fallback language.
- Formatters, such as money, go at the top level of `setup.ts`. A formatter gets the language as `lng` and must give the same text for the same language, options and value, since the server keeps translated strings (`build.i18next_cache` in `tifa.yaml`).
- Pass the language to `Intl` calls yourself. Without it the server writes `en-US` and `UTC` and the browser writes its user's, which breaks hydration. See [rendering.md](rendering.md#formatting-so-hydration-matches).
- The messages of `Validate` reach the visitor. Either read `c.Language()` in a `Validate(c *tifa.Ctx)` and return texts in that language, or return codes and translate them in the page.

## Links and the language switch

- Write links as if the site had one language: `<Link to="/store/cart">` becomes `/en-US/store/cart` on an `en-US` page. A link to a route outside the area, or to another language, loads a new page, because one document holds one language. `navigate`, redirects from `Load` and `tifa.Redirect` follow the same rule.
- For a switch, `useAlternates()` from `tifa/client` gives `{ language, url }` for each version of the page. Link to them with a plain `<a>`. The URLs carry no query string.

## Search engines and other versions

- On a page with several versions Tifa writes `hreflang` links for every version and `x-default` for the default one. Every page also gets a canonical link and an `og:url` with the same URL (an `og:url` in `head` wins), with the query parameters its Loads read and no other. They need `site.url`. There are none on a 404 or an error page, and no `hreflang` links on a page with one version. `/sitemap.xml` lists each version with the same links: give a page with translated slugs the same list in the `Alternates` of its `tifa.SitemapPage` (see `references/build-and-deploy.md#search-engines-and-language-models`).
- By default a page exists in every language of its area at the same path. When a page has another slug in another language or exists in one only, call `c.SetAlternates([]tifa.Alternate{{Language: "zh-CN", Path: "/store/journal/ni-hao"}, ...})` in its `Load`. Paths are escaped, without prefix or query, and include the page itself.
- A content collection with `Languages: tifa.Languages()` has a folder per language under `content/`. Read it with `Collection.Get(c.Language(), id)`. A missing entry is a 404.

## Choosing a language for a visitor

Tifa does not redirect by `Accept-Language` or a cookie. If the site wants that, write a `GET` handler on a route outside every area, with `Cache` off, that redirects to the language and adds `Vary: Cookie, Accept-Language`. Use 302. `golang.org/x/text/language` has a `Matcher` for `Accept-Language`.

## What fails the build

An area without a file for the default language, several languages with no `i18n.default` or no `site.url`, a file name that is not a language tag, a `_locales` folder with no file, a top-level folder of `app/` named like a language of the site, a `lang` in `htmlAttributes`.
