# A site in several languages

Contents: the pattern, the checking Layout, `lang` and alternate links, the redirect from `/`, translations, formatting.

Full docs: [app.md](https://github.com/liustack/tifa/blob/main/docs/app.md#a-site-in-several-languages). The storefront of the example shop under `/store` is a working copy: https://github.com/liustack/tifa/tree/main/examples/shop/app/store.

Tifa has no language settings. The language is part of the URL and Go checks it.

## The pattern

- Put the language in a parameter folder at the start of the URLs, such as `app/store/lang+`. Every URL names its language, the default one too: `/store/zh-CN/products`, `/store/en-US/products`.
- The `Layout` of that folder checks the language and returns it as data. An unknown language returns `tifa.ErrNotFound`, which shows the 404 of the Layout above.

```go
// app/store/lang+/route.go
func Layout(c *tifa.Ctx) (Shell, error) {
	l, err := storekit.FindLocale(c.Param("lang")) // tifa.ErrNotFound for a language the store does not have
	if err != nil {
		return Shell{}, err
	}
	return Shell{Locale: l, Menu: products.Menu(l)}, nil
}
```

- Pages and components take the language from that data (`layout.useLoaderData()` or a context the Layout component provides), never from `params`. The Go function checked it, so what someone types in the URL does not become the language of the page.
- A `Load` below the Layout checks the same way, or reads the Layout result with `tifa.Use(c, thatpkg.Layout)`.
- To show the storefront without the shell of another section, put a `layout_.tsx` in the folder above (`app/store`). It renders `<Outlet />` and an `Error` that shows the 404 of an unknown language in both languages, since the visitor's language is not known.

## lang on html, and alternate links

The `head` of the language Layout sets `lang` on `<html>` and links the same page in each language. Search engines read both. Take the language from the Layout data.

```tsx
// app/store/lang+/layout.tsx
const site = 'https://shop.example.com' // where the store is served
const languages = ['zh-CN', 'en-US'] // the default one first

export const head = ({ loaderData, matches }: { loaderData?: LayoutData; matches: Array<{ pathname: string; status: string; _notFound?: unknown }> }) => {
  if (!loaderData) return {}
  const { code } = loaderData.locale
  const common = { htmlAttributes: { lang: code } }
  if (matches.some((match) => match.status !== 'success' || match._notFound)) return common
  const page = matches[matches.length - 1].pathname.replace(/\/$/, '').slice(`/store/${code}`.length)
  const url = (lang: string) => `${site}/store/${lang}${page}`
  return {
    ...common,
    links: [
      ...languages.map((lang) => ({ rel: 'alternate', hrefLang: lang, href: url(lang) })),
      { rel: 'alternate', hrefLang: 'x-default', href: url(languages[0]) },
    ],
  }
}
```

- Leave the links out when any matched route failed or is a 404, since a URL that answers 404 is no page to point search engines to. The `lang` stays.
- `htmlAttributes` must be an object. The deepest route that sets an attribute wins, `undefined` leaves it to routes above, `null` removes it.
- Keep things a script changes on `<html>` (a dark mode `class`) in an attribute no route sets, such as `data-theme`, or Tifa may overwrite them on navigation.

## The URL without a language

A method handler in the folder above sends the visitor on: to the language saved in a cookie, else to the best match for `Accept-Language`. Use 302 and `Vary`, since the answer depends on the request. `Matcher` of `golang.org/x/text/language` knows that `en-GB` is closer to `en-US` than to `zh-CN`.

```go
// app/store/route.go
var codes = []string{"zh-CN", "en-US"} // the default language first

var matcher = language.NewMatcher([]language.Tag{language.MustParse(codes[0]), language.MustParse(codes[1])})

func GET(c *tifa.Ctx) error {
	c.Writer().Header().Add("Vary", "Cookie, Accept-Language")
	if picked, err := c.Cookie("lang"); err == nil && slices.Contains(codes, picked.Value) {
		return tifa.Redirect("/store/"+picked.Value, http.StatusFound)
	}
	tags, _, _ := language.ParseAcceptLanguage(c.Header("Accept-Language"))
	_, i, confidence := matcher.Match(tags...)
	if confidence == language.No {
		i = 0
	}
	return tifa.Redirect("/store/"+codes[i], http.StatusFound)
}
```

Here the folder has no `page.tsx`, so `GET` is allowed.

## Translations

- Load them synchronously. Bundle the messages of every language with the app and set the library up without waiting, such as i18next with `initAsync: false` and its `resources`. The server render waits for nothing and reads no files. Messages that arrive later are missing from the HTML, and the browser would hydrate with other text.
- Both sides take the language from the Layout data, so they show the same text.
- Create or switch the i18n instance from that data inside a component or provider, not in module scope that is shared across requests (see [rendering.md](rendering.md)). Setup that every page needs goes in the root Layout or a module it imports, because other route modules load lazily in the browser.
- i18next on the server keeps a cache of translated strings by default (`build.i18next_cache` in `tifa.yaml`). Turn it off only if the app changes i18next resources or options after the first render, or uses i18next functions that read request data. Then pages may show stale text with it on.

## Formatting numbers and dates

Use the locale and, for dates, a time zone from the same data. Without them the server writes `en-US` and `UTC` and the browser writes its user's, which breaks hydration. See [rendering.md](rendering.md#formatting-so-hydration-matches).
